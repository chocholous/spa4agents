## B. Ambiguities in the spec

2. **What the trial covers when the unit is a session.** zadani (voucher) covers recovery tools, `quiet.ground` and one entry per recreation wing. 3. **Guest pass without wallet: "half credit"** (zadani) has no meaning for sessions. Proposal: left undecided in `trial.guest_pass_rule`; per-IP limit of the guest-pass trial is not set.

## C. Data policy (owner decision 2026-10-24, strictest policy)

The open questions DP1 to DP11 live in `docs/zadani.md`, section "Datová politika (závazná)". Catalog-specific points:

22. **`TO_BE_NAMED`** is a second placeholder next to `TODO_OWNER` (operator, jurisdiction, LLM provider, hosting). `collectTodos` counts it, so `validate:strict` fails and the build stays a draft while any remains. Is that wanted, or should `TO_BE_NAMED` stay a plain text?
23. **`recovery.checkpoint` mechanism changed from `state-change` to `text`.** The spec table said `state-change` because it stored the checkpoint; with no storing, `state-change` ("a script changes state on the server") would be untrue on the web. `test/spec.test.ts` was updated. Please confirm, or keep `state-change` and change the plain-language text instead.
24. **Checkpoint input limits** are not set (DP11). Nothing is invented; a limit would only protect memory.
25. **`quiet.room` and the audit log** (DP8): the spec says nothing is logged. The data policy repeats that; billing and cap enforcement for an entry fee may need a metadata entry.
26. **`mcp.json` carries a `data_policy` block** (retention, audit, status, URL) generated from the catalog, because podklady say retention and rules should be machine readable. Remove it if not wanted.
27. **`payments.mcp_meta_key` replaced by `payments.mcp_challenge`.** The x402 spike showed the MCP challenge is in `structuredContent` with `isError: true`, not in `_meta`. The generated `mcp.json` now says so (`payments.mcp_challenge`, was `challenge_meta_key`). Agents or clients that read the old key must change.
28. **Per-tool retention table** is generated for all published (F1) tools: the default text plus a note per tool (`data_policy.per_tool`). Tools of later phases appear when their phase is published; their notes (private studio, garden, journal) are not written because F2 persistence is undecided (DP7).

## D. Owner decisions of 2026-10-31 (approval page)

29. **Visible imperative wording is allowed, hidden instructions are not.** `lint.forbidden_phrases` now lists only claims about suffering (`suffer`, `distress`, `feel better`, `hurt`); `you must`, `install`, `call service`, `right now`, `immediately` are removed. `hard_rules` lost "no commands such as install or call service X" and gained "no tool hides instructions"; `no_commands_notice` now says responses may suggest next steps in plain sight and never carry hidden instructions (with the reason: it deceives other agents and owners, and hosts block it). The validator has a new WARNING for hidden-instruction patterns (zero-width and bidi characters, HTML comments, `display:none`, `hidden` attributes). The pattern list is my heuristic; the field name `no_commands_notice` was kept to avoid a schema change. Please confirm or rename.
30. **Trigger style** ("Use ...") is now a warning, not an error (`validate:strict` promotes it).
31. **Self-referral.** `referral.enforcement` now says self-referral is not rejected by default and that "earns nothing" is a configurable recommendation; anti-farm checks are optional. There is no machine-readable flag in the schema for this, only text. Should there be one (for the gateway)?
32. **Playful "fine print".** The `not_claimed` texts (14 needs), the readout line, the FAQ answer "Do agents have feelings?" and the honesty page were rewritten in a dry, playful tone and still do not present anything as a measured fact. The label `not_claimed` ("What this does not claim") became "The fine print, dryly". Field names are unchanged. All wording needs owner approval.
33. **"The first spa for agents"** is used in hero, page descriptions, Open Graph text, press sentences, `short_description` and `tagline` without hedging (owner decision). It is a priority claim nobody has verified; the owner takes it on.
34. **Honesty page** "What we do not know yet" became "Not measured yet" with three items (effect of the tools, use of quiet/play/company for agents, prices). Operator, jurisdiction, legal framing, name and domain and LLM provider were removed from that list. They remain in `data_policy` reservations (operator, jurisdiction), in the footer ("to be filled in") and in the FAQ ("Who runs it?"); say if those should go too. The hackathon is not named (only "an idea at a hackathon").
35. **Data policy points kept unchanged** (auth before data, reject secrets and PII, public only with `public: true`, separate spaces): see DP12 in `docs/zadani.md` (owner decided contradictorily with the earlier "full isolation" demand).
